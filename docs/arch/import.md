# Architecture: import

Part of docs/ARCHITECTURE.md (§13); its rules bind the same way.

## 13. Import

Every source produces the same `ChartDraft`: a chart's `name`, `template` and `content` (§5), plus the products it was on, a status of `ready`, `check_units` or `unreadable`, and a plain reason for anything not ready. Drafts go through the chart validator like any other write.

| Source               | Step     | Reads                                           |
| -------------------- | -------- | ----------------------------------------------- |
| Kiwi Size Chart      | #35, #36 | The session shop's own storefront product pages |
| CSV                  | #75, #76 | Fitted's CSV template or a spreadsheet export   |
| Product descriptions | #37      | `descriptionHtml` from the Admin API            |
| Image, PDF           | #38      | An upload, read by OpenAI                       |
| Web page, Word       | #39      | A pasted link, or a .docx upload                |

Flow (#34): Find charts starts an `import` job (below). The review screen lists the drafts; Fix resolves `check_units`; Import creates the selected drafts as Draft charts with the handles of §5, so Try again re-runs only the failed ones and never duplicates; a draft already imported is skipped, never written again over a chart edited since. Their product assignments become `product` conditions (§6), reported per chart when they don't fit the id limit. Nothing goes live until the merchant publishes. A version row records "Imported from Kiwi" or the source.

Jobs: imports and full rule resolves run as `Job` rows (§14) inside the app process, with random ids (they appear in import handles), at most one running job per shop and kind, and progress saved as it goes, so a stopped scan offers the charts found so far. A job with no progress for 10 minutes is marked failed by a check that runs every minute and at server start (`checkJobs` in `app/models/rules.server.ts`, started by `app/entry.server.tsx`), so a job the old instance is still finishing during a deploy is left alone. A failed import is the merchant's to scan again. A failed resolve that is the shop's newest is requeued by that same check, since resolves are idempotent, but only for a shop with an offline session, so a resolve never brings back rows `shop/redact` deleted. A requeue is bounded: three tries in all, counted in `progress.attempt`, so a lasting failure stops until the merchant or the daily reconcile (§6) starts a resolve, which counts from one again. While one is failed the Display rules screen says the rules didn't finish applying, with Try again. A resolve job's `progress` is `{ merchant, pass, attempt }` (a requeue keeps `merchant` and adds one to `attempt`), its `result` `{ changed }`, and its `error` a plain reason, never Shopify's raw text. An action that starts a job first checks that the staff member can read products, because the job runs with the offline token (`canReadProducts`, #83). The newest finished job per shop and kind is kept (Home's setup guide reads it); others go after 7 days. `ponytail:` in-process jobs assume one Railway instance; move to a queue before running two.

Limits and safety:

- Uploads: CSV up to 1 MB, images (PNG, JPG, WebP) up to 10 MB, PDFs up to 20 MB and 10 pages, .docx up to 5 MB. An upload is read as a stream and cut off at its cap, never buffered whole first (`request.formData()` buffers). The type is checked by the file's first bytes, not its name. Every parse counts inflated bytes, whether .docx zip entries or PDF streams (page counting included), and refuses the file past 20 MB inflated. A .docx with a DOCTYPE is refused, so XML entities never expand. Files are processed in memory and never stored.
- Fetching: Kiwi and web-link reads go through one fetch helper, `safeFetch` in `app/models/import-fetch.server.ts`, added by #35 and reused by #37 and #39. It allows http and https on ports 80 and 443 only, follows at most 5 redirects, and checks the address actually dialed, at connect time, on every redirect, so DNS rebinding can't slip past. Only global unicast addresses pass: loopback, private, link-local, carrier-grade NAT, unique-local, IPv4-mapped, NAT64, 6to4, reserved, multicast and metadata addresses are refused. It has a 10-second timeout, and its 5 MB cap counts bytes after decompression. URLs found inside imported content (an image in a description) go through it too.
- Kiwi (#6 limits): only after the merchant clicks Find charts; only the session shop's `myshopify.com` domain and its `primaryDomain` from the Admin API, through the fetch helper; at most 2 requests a second; numbers and text only, no Kiwi images, logos or styling. Kiwi's charts are never in the page Shopify serves (#35 checked Kiwi's demo store): its app block prints only the product's data and a script that fetches the chart from Kiwi's own server (`app.kiwisizing.com`) in the shopper's browser. So `scanForKiwi` (`app/models/kiwi-import.server.ts`) samples product pages and returns why nothing was found: no products, a password-protected storefront, no Kiwi, or Kiwi with charts it can't read. Each gets the "nothing found" state with its reason, and CSV and image import as the way forward. Reading Kiwi's server is outside these limits and waits on the owner (#35). Re-check Kiwi's terms before launch.
- OpenAI: image and PDF import and translations go through one module, `app/models/openai.server.ts`, with `OPENAI_API_KEY`, the model name and an output-token cap in constants, structured JSON output, and a 60-second timeout. The model's answer is untrusted input: it is validated like any draft. Calls count against a shop budget of 100 a day (20 on Free and on development stores, which anyone can create) and an app-wide budget of 1,000 a day (`AiUsage`, §14). Past either, or when OpenAI refuses for quota (the organization has a hard $5 monthly cap for now), the merchant is told plainly and offered CSV.

CSV, in `app/models/csv-import.server.ts`: one row per size row. Export (#33, `app/routes/app.export.tsx`) writes every chart on every plan in Fitted's layout, where each row's first cell says what the row holds. Import reads that layout back (#75), and plain spreadsheets and the template (#76).

| First cell           | The cells after it                                                                                                                                                      |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Fitted size charts` | `1`, the layout's version. Always the file's first row.                                                                                                                 |
| `Chart`              | Name, template, unit, round to. Starts a chart.                                                                                                                         |
| `Settings`           | The chart's `measure`, `videoUrl` and `fit` (§5) as JSON.                                                                                                               |
| `Table`              | Id, title, subtitle, note. Starts a table.                                                                                                                              |
| `Columns`            | Blank, then `<id>:<type>` per column, type `size`, `text`, `US`, `UK`, `EU`, `AU`, `measure` or a unit (`in`, `cm`, `lb`, `kg`), with `:fixed` when `convert` is false. |
| `Labels`             | Blank, then each column's label.                                                                                                                                        |
| `Row`                | Row id, then a cell per column: `34` or `34–35.5` in measure columns, text in the others.                                                                               |
| `Merge`              | Row id, column id, rows, columns.                                                                                                                                       |
| `Wrap`               | Column ids.                                                                                                                                                             |
| `Text`               | Key, text: every word not placed above.                                                                                                                                 |
| `Error`              | Stands for a chart that failed validation, so it is named, not dropped.                                                                                                 |

Cells are comma-separated and quoted as RFC 4180 says, rows end with CRLF, and the file starts with a UTF-8 BOM so Excel reads it as UTF-8. A cell with no text is empty, an empty text is `""`, and a text with spaces around it is quoted; import keeps quoted cells as they are and trims the others.

Name, template and content survive a round trip unchanged; the How to measure image, a file in Shopify Files, isn't in the CSV. Opening the file in a spreadsheet and saving it can still turn a size such as `10-12` or `00` into a date or a number. In an edited export, a blank row id is generated and a column with no type is inferred as below. Any other file is one plain table (`public/fitted-template.csv` is the template), named after the file: the first row holds labels and the first column sizes. A `US`, `UK`, `EU` or `AU` label makes a country column; a unit in a label (`Chest (in)`, `Waist cm`) makes a measure column in that unit; otherwise a column whose filled cells are mostly numbers or ranges is a measure column, and any other is text. Lengths take the unit most labels name, and with none the draft is `check_units`. The delimiter is `,`, `;` or tab, whichever the first row uses most outside quotes; with `;`, numbers may use a decimal comma.

`importCsv` reads the upload itself, so the screen sends the file as the raw request body. The file must be UTF-8 (a BOM is fine) and is refused if it has a NUL byte or starts like a zip or a PDF. A bad cell or row makes only its chart `unreadable`, with a reason that names the row (and column) of each of its first five problems and counts the rest; the whole file is refused only when it is empty, over the cap, not UTF-8 text or has a quote that never closes, or when a Fitted file has another version, no charts, more than 1,000 charts or rows before its first `Chart`. A chart of 6,000 rows or more is too large to read; Fitted writes at most about 5,200. These bounds keep every file's work small on the one instance: 1 MB holds several hundred exported charts, more than the 200 display rules rank (§6), and past the cap or 1,000 charts the message says how to split an export: its first row atop each file, split only above a `Chart` row. So spreadsheets don't run text as a formula, export puts a `'` before every `=`, `+`, `-`, `@`, tab or carriage return that starts a cell or follows a semicolon, tab or line break (a spreadsheet may start a cell there too), counting any quotes or apostrophes already in front, and import removes one at each such place.
